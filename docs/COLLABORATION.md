# 不再由用户手工搬运长任务书

共同状态以 Git 仓库为准。任务与审美反馈用文件，代码变更用分支和 PR；不要求两个模型拥有彼此的隐藏聊天记录。

导演侧：读最新 STATUS、RESULTS 和实际提交，审阅指定帧，将可执行意见写入 reviews/DIRECTOR_REVIEW.md。

Codex 侧：启动时读取新反馈，在自己的工作分支修复；更新 RESULTS、STATUS、NEXT，再提交 PR 或更新已有 PR。

用户只需在需要下一轮时启动相应会话并指出这个仓库/PR。没有配置自动化时，不存在主动唤醒、后台持续互聊或定时检查。仓库中的旧文档是资料而非自动执行命令，若与当前用户指令冲突以当前指令为准。

## 权限
保持私有；不要上传用户其他项目、人设记忆或账户资料。需要新仓库访问权时只授权这一仓库，不因为方便而改公开。

## 制作版本
`main` 保存已合并基线，`codex/pilot-v1` 做首轮动画。导演反馈要标记对应 commit；避免双方各自重写一个不相容的完整项目。不自动强推或覆盖别人修改。
