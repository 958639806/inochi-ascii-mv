# 15 秒字符动画 — Codex 执行任务书 v1.1

> 继承对话中用户选择的 A 任务书；此版把时间区间、音频路径、复现性和交接要求具体化。
> 素材已就绪，动画工程尚未实现。禁止把本计划当作已渲染结果。

## 1. 制作目标
为《命に嫌われている》制作原创字符动画试片，表达“压抑控制 → 失稳 → 反噬 → 重组 → 余震”。让字符组成可辨识、有呼吸与姿态的人，而不是全屏随机噪声或歌词 PPT。

当前试片保留“模板化关怀系统”的视觉框架，但全曲主题还包括叙述者的自相矛盾。参考原始创作说明时，不把本试片宣称为对作者意图的唯一解释。第一次副歌不提前消费全曲最终求生高潮。

## 2. 硬规格与时间基准
- 1920×1080，60/1 FPS 恒定帧率，15.000 秒，900 帧。
- 本地时间 `t = frame / 60`，整曲对应 `58 + t`；范围 `[58, 73)` 秒。
- 片段音轨：`assets/audio/pilot_058-073.flac`，48 kHz / 24-bit / stereo，时长 15 秒。不要再次裁 58 秒。
- 最终 H.264 / MP4，yuv420p；AAC 320 kbps / 48 kHz 仅在最终合成时生成，不反复有损转码。
- 初次审美预览 960×540 / 60fps。先验证导出链和连续性，再生成正式 1080p60。
- `config/pilot.timeline.json` 为镜头边界的唯一机器来源。全曲草案仅供参考。
- 拟定镜头切换点未逐一校验鼓点。不要假设固定 BPM 从 t=0 对齐，不把音量峰值等同于歌词语义。

## 3. 八镜头执行表
每段均使用左闭右开区间；边界帧属于下一镜头，不重复画面或丢帧。

### S01｜压抑建立｜0.000–1.200 s｜帧 [0,72)
原曲 58.000–59.200。黑色终端空间，灰白字符人形在中央偏下。至少看出肩线、头部、手臂与站姿；胸口细微明灭。前后景各有少量悬浮窗口，远处字符尘缓慢漂移。
- 文案只出现少量：`LIFE VALUE: HIGH`、`EMPATHY RESPONSE READY`、`SUBJECT STATUS: UNSTABLE`。
- 相机极慢前推，保持稳定构图；微弱扫描纹与辉光，不强加全屏 CRT 噪声。
- 验收：静帧能分出主体、前景窗口与远景，角色不能只是一个球或矩形。

### S02｜语言围困｜1.200–2.500 s｜帧 [72,150)
原曲 59.200–60.500。窗口像自动回复般增殖并靠近角色。角色低头收缩，肩部出现掉字。镜头延续前推，略向下压；不能硬切成另一个场景。
- 核心对照：`EMPATHY SCORE: 98` 与 `ACTION TAKEN: NONE`。
- 只保留一组主文案可读，其他作为低亮度环境纹理；重要信息不能一闪而过。
- 验收：窗口应真实缩小可活动空间，而非只沿屏幕平移。

### S03｜信息过载｜2.500–4.000 s｜帧 [150,240)
原曲 60.500–62.000。窗体内文字脱离，形成横向条带、网状障碍和围墙。角色抬头，碰撞点局部碎裂，掉字被卷入文字流。相机加速，低幅度横向漂移。
- 逐渐增加密度与局部字符错位；特效不能淹没人物轮廓。
- 验收：可追踪“窗体 → 文本网 → 碰撞 → 身体掉字”的因果，不是随机刷屏。

### S04｜第一次爆裂｜4.000–5.500 s｜帧 [240,330)
原曲 62.000–63.500。文本墙压近，在预设事件点角色转为大量字符碎片，墙体同时断裂。镜头短促急推，穿入裂口；人物解体是抽象状态变化，不是写实受伤或死亡镜头。
- 爆裂粒子继承人体采样点 ID，后面能够回到对应位置。事件点先由分镜配置指定，听审后再微调。
- 用运动、局部亮度跃迁和稀密对比制造冲击；默认禁用全屏白闪、红白频闪。
- 验收：爆前能辨认人形；爆后方向有组织；不能只有随机噪点掩盖主体。

### S05｜后台反讽｜5.500–7.000 s｜帧 [330,420)
原曲 63.500–65.000。穿透表层 UI 后进入空旷的纵深日志空间。人体仍未完整，只留下与原胸口位置有联系的字符核心。日志慢速悬浮，核心脉动。
- 重点可读对照：`response automated` / `pain not processed`；其他 `queue full`、`case ignored` 作为次要碎片。
- 让此前的主角编号与后台操作者编号存在微弱呼应，作为全曲自我矛盾的伏笔，不额外解释整段故事。
- 验收：从拥挤到空旷的变化明确，镜头仍有空间连续性。不是临时切换到空白幻灯片。

### S06｜重组与穿透｜7.000–9.500 s｜帧 [420,570)
原曲 65.000–67.500。核心前进，原有碎片回流。躯干、手臂、头部逐步显现，角色沿路径前冲并拨开文字障碍。
- 使用同一组字符 ID、人体目标位置与有序汇聚曲线；保留缺口与掉字，不完美复原。
- 相机低机位跟拍，与角色的相对速度可控，不能让角色永远只是屏幕中心静止图标。
- 验收：观众能看出“刚才散开的字符组成同一个人”。

### S07｜顶点对峙｜9.500–11.800 s｜帧 [570,708)
原曲 67.500–69.800。角色进入前景半身，狼狈地向前迈一步，肩胸起伏明显。背后面板逐个失效，字符仍偶尔掉落。
- 只用一个状态词：`STATUS: ACTIVE`。不出现英雄胜利姿态、不出现全曲结语 `STILL ALIVE`。
- 背景降密度，镜头保留轻微运动；不能用“定格”偷掉此段动画。
- 验收：生命感来自姿态与呼吸，不只是胸前光点变亮。

### S08｜余震与钩子｜11.800–15.000 s｜帧 [708,900)
原曲 69.800–73.000。破碎空间中角色仍站立，碎片缓慢运动，远处日志继续坠落。镜头拉到中景并略升高，露出未消失的系统空间。
- 最后 1 秒有一次低亮度光标呼应，但不强行淡黑、结束歌曲或添加大结局字幕。
- 视觉降密度不代表音乐真的安静；本段仍是副歌内部，不得擅自把音量压低。
- 验收：末帧还能接回全曲；输出只到 frame 899。

## 4. 视觉统一
黑底、冷白与灰为主，少量青绿和暗红，总计不超过五个主色。主体、环境都由字符构成，必要的可读短文案单独排版，不使用整段歌词滚屏。

固定人体基础采样和姿态骨架，字符 ID 不随帧重抽。采用字符图集批量绘制，避免成千上万个独立 DOM 元素。字体不随包分发；首轮使用系统等宽字体并记录最终渲染环境，若需新增字体另核授权。

## 5. 模块与工程接口
建议 Vite + TypeScript + Three.js + GLSL + Vitest；Playwright 离线截图、FFmpeg 编码。
- `TimelineEngine`：镜头查询、关键帧与事件，不读真实系统时间。
- `CharacterBody`：人体采样、姿态、呼吸、碎裂、回收。
- `UISystem / TextStorm`：窗口、文本障碍、后台日志，所有位置由时间与种子求值。
- `CameraDirector`：连续相机轨迹，穿墙和跟拍段可测试。
- `PostFX`：有限辉光、错位、字符化；离线拖影不可依赖上一帧的残留缓冲。
- `AudioSync`：预览以播放时间显示；离线以帧号驱动，音频只参与最后合成。
- `RenderExport`：等待字体/场景/纹理加载完成，然后逐帧调用导出接口。

要求暴露 `window.renderFrame(frame, seed)` 和可等待的就绪信号。相同帧可从任意顺序调用，禁止用实时录屏作为正式逐帧导出的替代。跨硬件不承诺逐像素一致。

## 6. 开发顺序
A. 初始化与时间轴：先有一个可运行的人形+窗口镜头，能直接跳帧。
B. 爆裂与重组：验证同一组字符 ID 的往返，不先做复杂特效。
C. 打通八段：960×540 预览可看完 15 秒；所有转换连续。
D. 校准：听审片段，记录歌词/节拍对应与需调整的事件帧；不得声称已经得到其他模型评价。
E. 导出：先用少量帧验证流水线，再导出 900 帧 1080p60；检查 ffprobe、重复帧、首尾和同步。
F. 审美验收：交导演看真实接触表与视频，按反馈局部修改，保留已通过镜头。

## 7. 测试与交付
必须测试边界帧 0、71、72、149、150、239、240、329、330、419、420、569、570、707、708、899；900 应拒绝或明确仅作为非输出端点。

对关键帧先后乱序渲染再复测，验证同后端可复现；检查角色可见、相机有效、无 NaN。每镜头导出开始/中间/末尾供审阅。

交付：源码、锁文件、README、真实命令与测试日志、预览 MP4、固定关键帧、已知问题。没有真正生成的视频不得列为交付物。正式母版必须确认 1920×1080、60fps、900 帧及 15 秒音轨。

## 8. 范围控制
不新增后台服务、账号系统、多模型自动调度、整曲渲染或复杂角色资产。先有一个人形、三类窗口、一次围困、一次爆裂、一次重组与收尾。暂未实现的项写 BLOCKED 或 TODO，不悄悄删掉再声称全部完成。
